# Feed-Forward

Read at Step 11. Propose-only: log, count, propose. Nothing writes the brain or another skill.

## Mechanism

1. Each review, since and prep run appends `_patterns.md` (queue and ask never do): date, deal slug, segment, stage, gap types, play, buyer roles. No names, amounts or quotes except buyer phrases below.
2. A pattern is proposed only at the n below, counted as distinct deals inside 180 days. Below n it stays a note.
3. A proposal is exact text plus the receiving skill. The approver says yes, then runs the receiving skill. Unattended runs log and propose nothing. Never in a seller's thread.
4. `_mine.md` is never read here.

## Targets

| Observed | n | Proposed to |
|---|---|---|
| What buyers say the problem costs, verbatim, role and date | 1 | `product-marketing-context` (`customer_phrases`) |
| An objection, by role and stage | 2 | `product-marketing-context` (`objections`) |
| A DIY build, tool or status quo not in Section 3 | 2 | `alternatives-map` |
| A competitor in a live deal, with stage and role | 2 | `competitive-profile` (`intake`) |
| An incumbent in a deal | 1 | `competitive-battlecard` (offer only) |
| Where deals stall and which gap caused it | 3 | `product-messaging-playbook`, `positioning-messaging` |
| Champion, blocker and economic-buyer roles | 3 | `buyer-personas`, `stakeholder-maps` |
| Strong-fit deals that stall; anti-persona deals that close | 5 | `ideal-customer-profile` (audit) |
| A segment with a win rate | 10 per segment | `beachhead-segment` |
| A sales cycle length per segment, as the seller stated or the CRM showed | 1 | `ideal-customer-profile`, `product-marketing-context` (brain Section 2 `sales_cycle`; the field exists, and only that skill writes it) |
| A buyer-dated event before a real opportunity | 3 | `product-marketing-context` (`triggers`), `market-context` |
| A `prospect-research` signal that did or did not become a deal | 5 | `prospect-research` `_signals.md` |
| A discovery question that unlocked missing evidence | 3 | `product-messaging-playbook` |
| A won deal | 1 | `customer-context` (baseline) |
| A hypothesis worth testing on about ten deals | 1 | `experiment-doc` |
| Ledger rows | n/a | `meta-synthesis` via `/context/learning-sources.md` |

## Reads (read-only, each named on a "Learned from" line with skill and date)

Brain Sections 1, 2, 3, 5, 6, 8; the `prospect-research` record for the account (did the hypothesis hold); `customer-context` `_patterns.md` for the segment; `/context/battlecards/` and `_outcomes.md` when a rival is present; `/context/competitor-profiles/`. Learned items shape questions and steps; they never become proof of ours. A conflict with a confirmed brain value is shown as a question with both values.

## Rules

- A seller-reported outcome is labelled seller-reported.
- A hit rate shows only at 10 or more deals; below that, counts.
- A proposal that conflicts with a confirmed brain value is a question, not a replacement.
