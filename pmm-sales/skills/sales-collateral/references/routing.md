# Routing

Read at Pre-flight when the ask is not plainly one of the five assets this skill builds. Most mistakes here are building a sibling's asset because the ask said "enablement". Route first.

## How to route

1. **Find the asset noun** in the ask: one-pager, objection, battlecard, playbook, persona, case study, proposal, script, deck.
2. **Find the moment:** a live deal today, a reusable library, a document a buyer will read, or an analysis of past deals.
3. **Look up the owner** below. If a sibling owns it, send the ask there.
4. **Send, do not half-build.** One line: the skill, its command, and what you already have to pass along. Then stop, unless the ask also names an asset this skill owns.
5. **Two assets in one ask:** build yours; route the rest, one line each.
6. **Unclear asset** ("something for the sales team", "enablement material"): one question with the three likeliest assets, no draft.

Routing line shape: `That one belongs to objection-handling (/pmm-sales:objection-handling). I'll pass it the CFO's words and the Marlow stage so you don't retype them.`

## Owners

The owner table and each command live in `SKILL.md` Pre-flight, once. This file holds the steps above and the edge cases below.

## Stays here

One-pager or leave-behind, demo script or talk track, proposal, ROI calculator, deck outline, win-loss analysis. Nothing else.

## Edge cases

- **A one-pager that lists objections:** build it here, but take each response from the approved `objection-handling` card; never improvise one.
- **A leave-behind that compares us to a named rival:** build it here for a buyer, rival claims from `competitive-battlecard` or `competitive-profile` with their dates. A public page for search is `comparison-page-brief`.
- **A one-pager from a case study:** `customer-stories` owns the story and its approval; embed only the approved version.
- **"An enablement kit for the launch":** the launch handoff is `product-messaging-playbook`. Route it, and say in the same line that a one-pager, demo script or deck outline for the launch is built here. Do not ask first; the routing line already offers both.
- **A playbook for the whole sales motion:** not built. Offer the pieces that exist: `product-messaging-playbook`, `objection-handling`, `competitive-battlecard`, `discovery-call-prep`.
- **A proposal with an email:** the proposal here, the email to `writing-assistant`.
- **A deck:** the outline here; "make the slides" is a Slides job.
- **Win-loss from interviews:** `interview-summary` structures each interview; `winloss` here codes across them.
- **An existing customer's QBR or renewal deck:** `customer-context`.
- **Pricing and packaging, rep training, lead scoring:** not in this repo; say so.
