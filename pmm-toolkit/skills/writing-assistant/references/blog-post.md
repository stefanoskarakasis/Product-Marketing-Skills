# Blog post

## Inputs beyond the shared set

- The primary keyword and the search intent: what the searcher is trying to get done.
- The funnel stage and the product tie-in for the CTA.
- If the user hasn't pasted keyword data, do not state search volume, difficulty, or
  rankings. Write `[PLACEHOLDER: volume and difficulty from your SEO tool]`.

Default length: 900 to 1,200 words, unless the user names another target.

## Structure

1. **Headline.** Three options. Each includes the primary keyword and is short enough to
   show in full in a search result.
2. **Opening.** Deliver on the search intent inside the first screen, say what the post
   covers, and put the primary keyword in the first paragraph. Hook options: a real
   statistic (sourced, or a placeholder), a scenario the reader recognizes, a short true
   story from the team, or a plain claim the post then backs up.
3. **Body.** Three to five sections, each under a descriptive H2. One idea per section.
   Give the answer first, then the evidence. Each section carries at least one concrete
   example or sourced data point. Add a heading wherever the topic shifts. Keep
   paragraphs short.
4. **Ending.** The last concrete takeaway and one CTA that matches the funnel stage. Do
   not recap the post.
5. **SEO block.** Meta description, URL slug, secondary keywords used, internal link
   suggestions, external sources worth citing, image alt-text ideas, and any section
   shaped for a featured snippet. See `seo-checklist.md`.

## Rules

- Write for people first. Never stuff keywords.
- Active voice.
- Plain language for a broad audience; more technical only when the audience expects it.
- Every statistic is sourced by the user or the brain, or it is a placeholder.
